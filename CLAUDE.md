# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The **shared reproducibility core** for the Ethical Alpha Audit public stack: a deterministic harness, the authoritative public governance engine, configuration contracts, and archival notebooks. It is **not** a paper-specific submission repository. Paper repos consume verified copies of governed files from here; drift is detected via the parity manifest (see "Shared-logic parity" below).

Every result is a governance verdict produced by `engine/corrected_public_engine_v1_1.py` from inputs hardcoded in source, written to `outputs/`, and pinned by SHA-256 in `config/expected_outputs.json`. There are no external datasets.

## Common commands

```bash
# Full reproduction + validation (only supported entry point)
python reproduce_all.py

# Verify outputs match SHA-256 pins WITHOUT re-executing notebooks
python scripts/validate_outputs.py

# Run the test suite
pytest

# Run a single test
pytest tests/test_harness_structure.py::test_eaa_package_exports_repo_root

# Install pinned dependencies
python -m pip install -r requirements.txt
```

`reproduce_all.py` runs six ordered steps and fails fast on any one:
1. `scripts/validate_notebook_standard.py` — checks `expected_outputs.json` matches `baseline_output_hashes.json`, `trace_map.json` covers every planned notebook + expected output
2. `scripts/notebook_runner.py` — executes the notebooks in `config/notebook_plan.json` with `PYTHONHASHSEED=0`
3. `scripts/hash_manifest.py` — SHA-256s every declared output into `logs/actual_manifest.json`
4. `scripts/validate_outputs.py` — compares the manifest against `config/expected_outputs.json` pins
5. `scripts/export_html.py` — regenerates HTML exports under `docs/notebook_exports/`
6. `scripts/verify_shared_logic_parity.py` — verifies every governed file's bytes match `config/shared_logic_manifest.json` (reads `git show HEAD:<path>` to avoid CRLF false-fails on Windows)

## Architecture

The pipeline has one shape: **fixed inputs → engine → text/CSV outputs → SHA-256 pins**. Determinism is the contract.

### Authoritative engine

`engine/corrected_public_engine_v1_1.py` is the single source of governance logic. It is stdlib-only (no numpy/pandas). All notebooks add `engine/` to `sys.path` and `import corrected_public_engine_v1_1` — they never reimplement gate or compensatory logic. The engine has two evaluation modes:
- `replay_mode` (default): 5-gate + compensatory scoring
- `canonical_full_mode`: adds SCM abstention/fallback override

The 5 gates, compensatory weights, and threshold profiles (`permissive`/`moderate`/`strict`) are locked constants at the top of the engine module.

### Execution chain

The harness executes **only** the three "technical execute" notebooks (`notebooks/archival_shared/technical/*_execute.ipynb`) in the order set by `config/notebook_plan.json`. Each technical notebook is paired with a story notebook (markdown-only, rendered on NBViewer) and an interactive notebook (ipywidgets, served by Voila). Story and interactive notebooks are **not** in the validation chain — never add them to `notebook_plan.json`.

### Configuration contracts (`config/`)

These four files form a coupled contract. Changing one usually requires updating others:

| File | Contract |
|------|----------|
| `notebook_plan.json` | Ordered execution list (technical notebooks only) |
| `expected_outputs.json` | Declared output paths + SHA-256 pins |
| `baseline_output_hashes.json` | Must equal `expected_outputs.json` byte-for-byte (enforced by `validate_notebook_standard.py`) |
| `trace_map.json` | output_path → notebook + role; every notebook in the plan must claim ≥1 output; every expected output must appear here |
| `harness_settings.json` | `python_hash_seed`, timeouts, output-clearing, fail-fast |
| `shared_logic_inventory.json` | Enumerated list of governed files (no wildcards) |
| `shared_logic_manifest.json` | SHA-256 of every governed file; regenerated by `scripts/hash_shared_logic.py` |
| `engine_authority.json` | Documents the engine canonicality and supersession process |

### Python package layout

- `eaa/` — shared archival package. `eaa.paths.repo_root()` is the **only** repo-root discovery surface (uses `EAA_REPO_ROOT` env override or anchor-file scan). `eaa.notebooks.archival` holds notebook presentation logic; helpers under `notebooks/` thin-re-export from here rather than duplicating.
- `engine/` — authoritative governance engine module
- `src/` — intentionally empty placeholder; library code lives under `eaa/` and `engine/` by design (do not add code under `src/`)

### Outputs layout

- `outputs/tables/*.csv` — tabular artefacts
- `outputs/figures/*.txt` — narrative summaries (text, not graphical — graphical figures belong in paper-specific repos)
- `outputs/` contains validation artefacts **only**; everything in it is hash-locked

## Working in this repo

- **Do not edit `outputs/`, `logs/actual_manifest.json`, or any file in `config/` by hand** unless you intend to update the locked contract. Outputs are byte-pinned; manual edits cause `VALIDATION FAILED`. To change a pin, regenerate the output via the harness and update both `expected_outputs.json` and `baseline_output_hashes.json` (they must stay identical).
- **Engine changes** require: (1) a documented decision per `engine_authority.json`, (2) regenerating `shared_logic_manifest.json` via `scripts/hash_shared_logic.py`, (3) regenerating outputs + updating both hash files if outputs change.
- **Adding a new governed file** means listing it in `shared_logic_inventory.json` (wildcards are not used) and regenerating the manifest.
- **Adding a new output** means: produce it from a technical notebook, register it in `expected_outputs.json` + `baseline_output_hashes.json` + `trace_map.json`, then run `reproduce_all.py` to confirm.
- **Determinism rules:** stdlib-only in the engine; `PYTHONHASHSEED=0` set by harness; no time/random/UUID/network in execution paths.
- **Windows note:** `verify_shared_logic_parity.py` reads `git show HEAD:<path>` rather than the working tree so `.gitattributes` CRLF normalization doesn't produce false hash mismatches. Preserve that pattern if extending the parity script.

## CI

`.github/workflows/reproduce.yml` runs `python reproduce_all.py` on Python 3.11 on `push` to `main`/`stage2-r2-align` and `pull_request` to `main`. Any pin mismatch fails CI.
